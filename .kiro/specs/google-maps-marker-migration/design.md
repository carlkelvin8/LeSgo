# Google Maps Marker Migration Bugfix Design

## Overview

This design addresses the deprecation warnings generated by the Flutter web app when using the `google_maps_flutter` package. The warnings indicate that `google.maps.Marker` is deprecated as of February 21st, 2024, and should be replaced with `google.maps.marker.AdvancedMarkerElement`. The fix involves updating the Flutter Google Maps configuration to use the modern marker API while preserving all existing functionality across mobile and web platforms.

## Glossary

- **Bug_Condition (C)**: The condition that triggers deprecation warnings - when Google Maps markers are displayed on Flutter web using the deprecated `google.maps.Marker` API
- **Property (P)**: The desired behavior when markers are displayed - no deprecation warnings should appear in the browser console while maintaining identical visual and functional behavior
- **Preservation**: Existing marker functionality, visual appearance, and mobile platform behavior that must remain unchanged by the fix
- **GoogleMap Widget**: The Flutter widget in `google_maps_flutter` package that renders Google Maps with markers
- **AdvancedMarkerElement**: The modern Google Maps JavaScript API for creating markers that replaces the deprecated `google.maps.Marker`
- **markerType**: The GoogleMap widget property that controls which marker implementation is used on web platforms

## Bug Details

### Bug Condition

The bug manifests when the Flutter web app displays Google Maps with markers using the default marker implementation. The `google_maps_flutter` package defaults to using the deprecated `google.maps.Marker` API on web platforms, which generates console warnings.

**Formal Specification:**
```
FUNCTION isBugCondition(input)
  INPUT: input of type GoogleMapRenderContext
  OUTPUT: boolean
  
  RETURN input.platform == 'web'
         AND input.hasMarkers == true
         AND input.markerType == GoogleMapMarkerType.normal
         AND deprecationWarningsEnabled == true
END FUNCTION
```

### Examples

- **Web App with Markers**: Loading the lesgo booking screen with pickup/destination markers displays: "As of February 21st, 2024, google.maps.Marker is deprecated. Please use google.maps.marker.AdvancedMarkerElement instead."
- **Rider Map Screen**: The rider app map showing driver location markers generates multiple deprecation warnings in the browser console
- **Location Selection**: Using the address selection map widget with location markers triggers deprecation warnings during map interaction
- **Mobile Platforms**: iOS and Android apps should continue working without any changes or warnings

## Expected Behavior

### Preservation Requirements

**Unchanged Behaviors:**
- Mobile platform functionality (iOS/Android) must continue to work exactly as before using native map implementations
- Marker visual appearance (icons, colors, positioning) must remain identical on all platforms
- Marker interaction behavior (tap events, info windows, clustering) must continue to function as expected
- Map performance and rendering speed must not be negatively impacted

**Scope:**
All inputs that do NOT involve web platform marker rendering should be completely unaffected by this fix. This includes:
- Native mobile map rendering on iOS and Android
- Map interactions without markers (panning, zooming, map type changes)
- Non-marker map features (polylines, polygons, circles, overlays)

## Hypothesized Root Cause

Based on the bug description and code analysis, the most likely issues are:

1. **Default Marker Type Configuration**: The `GoogleMap` widgets throughout the app are not explicitly setting the `markerType` property, causing them to default to `GoogleMapMarkerType.normal` which uses the deprecated API on web

2. **Package Version Compatibility**: The current `google_maps_flutter: ^2.17.0` package supports advanced markers but requires explicit configuration to enable them

3. **Web API Configuration**: The web `index.html` already loads the modern marker library (`libraries=marker`) but the Flutter widgets are not configured to use it

4. **Missing Global Configuration**: There's no centralized configuration to ensure all GoogleMap widgets use the modern marker API consistently

## Correctness Properties

Property 1: Bug Condition - Web Marker Deprecation Elimination

_For any_ web platform rendering where markers are displayed on Google Maps (isBugCondition returns true), the fixed GoogleMap widgets SHALL use `GoogleMapMarkerType.advancedMarker` to eliminate deprecation warnings while maintaining identical marker functionality.

**Validates: Requirements 2.1, 2.2, 2.3**

Property 2: Preservation - Cross-Platform Functionality

_For any_ platform that is NOT web (mobile iOS/Android) or any map usage that does NOT involve markers (isBugCondition returns false), the fixed code SHALL produce exactly the same behavior as the original code, preserving all existing functionality for non-web platforms and non-marker map features.

**Validates: Requirements 3.1, 3.2, 3.3, 3.4**

## Fix Implementation

### Changes Required

Assuming our root cause analysis is correct:

**Files to Modify**: Multiple GoogleMap widget implementations across the app

**Primary Changes**:
1. **Update MapWidget**: Add `markerType: GoogleMapMarkerType.advancedMarker` to the main map widget
   - File: `FRONTEND/lib/presentation/widgets/global/googlemaps/map_widget.dart`
   - Add the markerType property to the GoogleMap constructor

2. **Update Location Provider Maps**: Configure advanced markers in location-related map widgets
   - Files: Various map widgets in booking, tracking, and location screens
   - Ensure consistent markerType configuration across all GoogleMap instances

3. **Create Centralized Map Configuration**: Establish a consistent pattern for GoogleMap widget configuration
   - Consider creating a base map widget or configuration constants
   - Ensure all new GoogleMap widgets use the modern marker API by default

4. **Verify Web Dependencies**: Confirm the web `index.html` has the correct Google Maps API configuration
   - File: `FRONTEND/web/index.html` (already correctly configured with `libraries=marker`)

5. **Update Package Dependencies**: Ensure the `google_maps_flutter` package version supports advanced markers
   - File: `FRONTEND/pubspec.yaml` (already using `^2.17.0` which supports advanced markers)

### Specific Implementation Steps

1. **Update Core Map Widget**:
   ```dart
   GoogleMap(
     // ... existing properties
     markerType: GoogleMapMarkerType.advancedMarker,
   )
   ```

2. **Identify All GoogleMap Instances**: Search for all GoogleMap widget usage across the codebase and apply the markerType configuration

3. **Test Web Platform**: Verify that deprecation warnings are eliminated while marker functionality remains intact

4. **Verify Mobile Platforms**: Ensure iOS and Android continue to work without any regressions

## Testing Strategy

### Validation Approach

The testing strategy follows a two-phase approach: first, surface counterexamples that demonstrate the deprecation warnings on unfixed code, then verify the fix eliminates warnings while preserving all existing functionality.

### Exploratory Bug Condition Checking

**Goal**: Surface counterexamples that demonstrate the deprecation warnings BEFORE implementing the fix. Confirm or refute the root cause analysis. If we refute, we will need to re-hypothesize.

**Test Plan**: Open the Flutter web app in a browser with developer console open and navigate to screens with Google Maps markers. Run these tests on the UNFIXED code to observe deprecation warnings and understand the root cause.

**Test Cases**:
1. **Booking Screen Test**: Navigate to lesgo booking screen and observe console warnings when markers appear (will show warnings on unfixed code)
2. **Location Selection Test**: Use address selection with map markers and check for deprecation warnings (will show warnings on unfixed code)
3. **Rider Map Test**: Open rider map screen with location markers and monitor console output (will show warnings on unfixed code)
4. **Mobile Platform Test**: Test the same screens on iOS/Android to confirm no warnings appear (should work correctly on unfixed code)

**Expected Counterexamples**:
- Browser console shows "google.maps.Marker is deprecated" warnings when markers are displayed
- Possible causes: default markerType configuration, missing advanced marker enablement, incorrect web API setup

### Fix Checking

**Goal**: Verify that for all inputs where the bug condition holds, the fixed function produces the expected behavior.

**Pseudocode:**
```
FOR ALL input WHERE isBugCondition(input) DO
  result := renderGoogleMapWithMarkers_fixed(input)
  ASSERT noDeprecationWarnings(result) AND markersDisplayCorrectly(result)
END FOR
```

### Preservation Checking

**Goal**: Verify that for all inputs where the bug condition does NOT hold, the fixed function produces the same result as the original function.

**Pseudocode:**
```
FOR ALL input WHERE NOT isBugCondition(input) DO
  ASSERT renderGoogleMap_original(input) = renderGoogleMap_fixed(input)
END FOR
```

**Testing Approach**: Property-based testing is recommended for preservation checking because:
- It generates many test cases automatically across different platforms and configurations
- It catches edge cases that manual unit tests might miss
- It provides strong guarantees that behavior is unchanged for all non-web marker scenarios

**Test Plan**: Observe behavior on UNFIXED code first for mobile platforms and non-marker map features, then write property-based tests capturing that behavior.

**Test Cases**:
1. **Mobile Platform Preservation**: Verify iOS and Android map functionality continues to work identically after fix
2. **Non-Marker Map Features**: Verify polylines, polygons, and other map features work correctly after fix
3. **Marker Functionality Preservation**: Verify marker interactions (tap, info windows) work identically on web after fix
4. **Performance Preservation**: Verify map rendering performance is not negatively impacted by the fix

### Unit Tests

- Test GoogleMap widget configuration with different markerType values
- Test marker creation and display on web platform with advanced markers enabled
- Test that mobile platforms continue to use appropriate native marker implementations
- Test edge cases (no markers, single marker, multiple markers, custom marker icons)

### Property-Based Tests

- Generate random map configurations and verify no deprecation warnings appear on web
- Generate random marker sets and verify identical visual appearance across marker types
- Test marker interactions across many scenarios to ensure behavioral consistency
- Verify performance characteristics remain within acceptable bounds across platforms

### Integration Tests

- Test full app flow with Google Maps on web platform without console warnings
- Test switching between different map screens and verify consistent marker behavior
- Test that existing user workflows (booking, tracking, location selection) work identically after fix
- Test cross-platform compatibility to ensure mobile apps remain unaffected
